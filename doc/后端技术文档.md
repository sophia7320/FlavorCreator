## 1. 系统架构

### 1.1 技术架构

```
┌─────────────────────────────────────────────────┐
│                  微信小程序（miniprogram/）          │
└──────────────────────┬──────────────────────────┘
                       │ HTTPS
┌──────────────────────▼──────────────────────────┐
│              Spring Boot 4.0.4（backend/）         │
│  ┌──────────────────────────────────────────┐   │
│  │  Controller 层（@RestController）          │   │
│  │  - AuthController  - CommunityController  │   │
│  │  - RecipeController - IngredientController│   │
│  │  - UserInfoController - ImageController   │   │
│  └──────────────┬───────────────────────────┘   │
│  ┌──────────────▼───────────────────────────┐   │
│  │  Service 层（接口 + @Service 实现）         │   │
│  │  - RecipeGenerateService（LLM 集成）       │   │
│  │  - ImageUploadService（文件上传）           │   │
│  │  - RefreshTokenService（令牌管理）          │   │
│  └──────────────┬───────────────────────────┘   │
│  ┌──────────────▼───────────────────────────┐   │
│  │  Mapper 层（MyBatis-Plus BaseMapper）      │   │
│  └──────────────┬───────────────────────────┘   │
└─────────────────┼───────────────────────────────┘
                  │
   ┌──────────────┼──────────────┐
   ▼              ▼              ▼
┌──────┐    ┌─────────┐   ┌──────────────┐
│MySQL │    │ Redis   │   │ SiliconFlow   │
│ 8.0  │    │ (可选)   │   │ LLM API      │
└──────┘    └─────────┘   └──────────────┘
```

### 1.2 分层原则

| 层 | 职责 | 约束 |
|----|------|------|
| Controller | 接收 HTTP 请求、参数校验（`@Valid`）、调用 Service、返回 `Response<T>` | 不直接调用 Mapper |
| Service | 业务逻辑、事务管理（`@Transactional`） | 抛出 `BusinessException`，不抛出 `RuntimeException` |
| Mapper | 数据库 CRUD | 继承 `BaseMapper<Entity>`，不写 SQL 除非复杂查询 |

### 1.3 跨模块引用规则

- **跨模块数据访问**：直接注入目标模块的 **Mapper**，不注入 Service（避免循环依赖）
- **认证上下文**：通过 `UserContext.getUserId()`（ThreadLocal）获取用户 ID，不在方法签名中传递

### 2.2 auth — 认证模块

**端点:**
- `POST /api/auth/login-wx` — 微信登录（`@Public`）
- `POST /api/auth/refresh` — 刷新 Token（`@Public`）
- `POST /api/auth/logout` — 登出

**流程:**
1. 小程序传入微信 `code`
2. `WxMaService.getUserService().getUserInfo()` 换取 `openid` + `unionid`
3. 查询 `User` 表，不存在则创建
4. 签发 JWT（`userId` + `openid`）和 refresh token（UUID 存 Redis/内存）
5. 返回 `LoginResponseDTO`

**Token 生命周期:**

| Token 类型 | 有效期 | 存储 |
|-----------|--------|------|
| 访问 Token（JWT） | 5 分钟 | 客户端持有 |
| 刷新 Token | 30 天 | Redis / `ConcurrentHashMap` |

### 2.3 recipe — 菜谱模块

**核心功能:**
- 菜谱 CRUD（发布、列表、详情）
- AI 菜谱生成（见第 6 节）
- 食材匹配推荐（`apply` 端点）

**数据库字段说明:**

| 字段 | 类型 | 说明 |
|------|------|------|
| `ingredients` | MySQL JSON | 食材列表 `[{"name":"鸡蛋","quantity":3,"unit":"个"}]` |
| `steps` | MySQL JSON | 烹饪步骤 `[{"order":1,"description":"..."}]` |
| `tags` | MySQL JSON | 标签 `["快手","下饭"]` |
| `difficulty` | INT | 1=简单, 2=中等, 3=困难 |
| `source` | INT | 1=系统, 2=用户, 3=AI |

### 2.4 community — 社区模块

**核心功能:**
- 点赞/取消点赞（原子增减 `like_count`）
- 收藏/取消收藏（原子增减 `collection_count`）
- 评论（一级 + 二级回复）

**实体关系:**
```
User ──< Like >── Recipe
User ──< Collection >── Recipe
User ──< Comment >── Recipe
Comment ──< Comment（自引用 parent_comment_id）
```

### 2.5 ingredient — 食材模块

**核心功能:**
- 食材 CRUD（增删改查）
- 调料管理（`category = "调味品"`，复用 `IngredientService`）
- 过期提醒（四级状态动态计算 + 三层堆缓存）
- 已读确认（单条/批量）

**过期状态计算规则（`IngredientStatus.compute()`):**

| 距离过期天数 | 状态 | code | 说明 |
|-------------|------|------|------|
| < 0 天 | EXPIRED | 0 | 已过期 |
| 0-3 天 | URGENT | 1 | 红灯 |
| 4-15 天 | WARNING | 2 | 黄灯 |
| > 15 天 | NORMAL | 3 | 绿灯（不入堆缓存） |

**堆缓存（`IngredientHeapCache`）:**
- 三个 `PriorityQueue`（按 `expireDate` 升序）：expiredHeap / urgentHeap / warningHeap
- NORMAL 不入堆
- 全量刷新：每 30 天重置，查询 `expireDate ≤ 30天` 的食材
- 增量同步：add/update/delete 实时同步堆
- 每日迁移：堆顶按当前状态重新分类，迁移的 `readed=false`
- 过期清理：`readed=true` 或过期超 365 天 → 从 expiredHeap 移除
- 双实现：`InMemoryIngredientHeapCache` / `RedisIngredientHeapCache`，通过 `flcr.cache.type` 切换

**定时任务（`IngredientSchedulerService`）:**
- 每 30 天 3AM：全量重建堆缓存
- 每天 2AM：堆迁移 + 过期清理 + 微信订阅消息推送

### 2.6 user — 用户模块

**核心功能:**
- 个人资料查询/更新
- 偏好设置（口味、饮食限制、烹饪偏好）
- 头像/背景图上传
- 我的发布/点赞/收藏聚合查询

### 2.7 common — 公共模块

**核心组件:**

| 组件 | 职责 |
|------|------|
| `AuthInterceptor` | 拦截 `/api/**`，解析 JWT 写入 `UserContext`，`@Public` 跳过 |
| `LoggingAspect` | AOP 日志，记录方法入参/出参/耗时，敏感字段（token/password/code）脱敏 |
| `GlobalExceptionHandler` | 统一异常处理：`BusinessException` → 对应错误码 + message，参数校验异常 → 400，其他 → 500 |
| `Response<T>` | 统一响应包装 `{code, message, data}` |
| `JwtTokenUtil` | JWT 签发、验证、解析 |
| `BusinessException` | 业务异常（code + message），唯一允许从 Service 层抛出的异常类型 |

## 4. API 设计

### 4.1 统一响应格式

```json
{
  "code": 200,
  "message": "success",
  "data": { ... }
}
```

### 4.2 错误码

| 错误码 | 常量 | 说明 |
|--------|------|------|
| 200 | `SUCCESS` | 成功 |
| 400 | `PARAM_ERROR` | 参数错误 |
| 401 | `USER_NOT_EXIST` | 未登录 |
| 402 | `USER_EXIST` | 用户已存在 |
| 403 | `PERMISSION_ERROR` | 权限不足 |
| 404 | `RESOURCE_NOT_EXIST` | 资源不存在 |
| 500 | `SYSTEM_ERROR` | 系统错误 |
| 1001 | `WX_CODE_ERROR` | 微信 code 无效 |
| 2001 | `IMAGE_TYPE_ERROR` | 图片格式错误 |
| 2002 | `IMAGE_SIZE_ERROR` | 图片大小超限 |
| 2003 | `IMAGE_MODERATION_FAILED` | 内容审核不通过 |

### 4.3 分页规范

- 请求参数：`page`（默认 1）、`size`（默认 20）
- 响应：`Page<T> { records, total, current, size }`

### 4.4 DTO 规范

- **请求 DTO**：`@Data`，命名 `XxxRequestDTO`，内部静态类加 `@NoArgsConstructor`
- **响应 DTO**：`@Data @Builder @NoArgsConstructor @AllArgsConstructor`（四合一），命名 `XxxResponseDTO`
- 需要校验的字段加 `@Valid` + Jakarta Validation 注解（`@NotBlank`、`@Size`、`@Min` 等）

## 5. 认证与安全

### 5.1 认证流程

```
请求进入 → AuthInterceptor.preHandle()
  ├── 非 HandlerMethod → 放行
  ├── @Public 注解 → 有 Token 则解析写入 UserContext，无则放行
  └── 无 @Public → 必须有 Token，否则 401
```

### 5.2 安全措施

| 措施 | 实现 |
|------|------|
| JWT 签名 | HMAC256 + 可配置密钥 |
| Token 刷新 | 一次性 refresh token（刷新后旧 token 失效） |
| 日志脱敏 | `LoggingAspect` 对 token/password/code/secret/key 参数输出 `***` |
| 密码加密 | BCrypt（`PasswordUtil`） |
| CORS | `/api/**` 允许，使用 `allowedOriginPatterns` |
| 参数校验 | Controller 层 `@Valid` + DTO Jakarta Validation |
| 异常处理 | `GlobalExceptionHandler` 统一捕获，不泄漏堆栈 |

### 5.3 用户隔离

Service 层通过 `UserContext.getUserId()` 获取当前用户，**不在方法签名中传递 userId**。这确保：
- 不会出现用户 A 操作用户 B 的数据
- 测试时通过 `UserContext.setUserId()` 模拟

## 6. AI 菜谱生成

### 6.1 架构

```
RecipeController.generateRecipe()
  → RecipeGenerateServiceImpl.generateRecipe()
    → buildSystemPrompt()       # 构建提示词
    → LlmClient.generateRecipeJson()  # 调用 LLM API
    → parseResponse()           # 解析 JSON 响应
```

### 6.2 提示词设计

提示词包含以下部分：

1. **输出格式铁律**：必须以 `{` 开头 `}` 结尾，列举三种常见错误示例
2. **JSON 结构模板**：明确每个字段的类型和示例值
3. **字段类型约束**：cookTime/calories/quantity/order 必须是纯数字
4. **步骤写作规范**：要求包含火候、时长、判断标准
5. **食材原则**：基础调料默认可用，非必要不增加额外主要食材

### 6.3 容错机制

1. **类型容错**：`FlexibleIntegerDeserializer` — 能将 `"30分钟"`、`"250大卡"` 等带单位的字符串解析为纯数字
2. **格式容错**：正则提取 `{...}` 作为 JSON 解析的兜底（处理 LLM 返回前缀/后缀文字的情况）
3. **空值防御**：解析后校验 `recipe != null`，否则抛出 `BusinessException`

### 6.4 LLM 配置

```yaml
llm:
  api:
    url: https://api.siliconflow.cn/v1/chat/completions
    model: Pro/zai-org/GLM-4.7
    key: ${LLM_API_KEY}
```

## 7. 文件存储与审核

### 7.1 存储策略

| 实现类 | 条件 | 说明 |
|--------|------|------|
| `LocalFileStorageServiceImpl` | `flcr.storage.type=local`（默认） | 存储到本地文件系统 |
| `CosFileStorageServiceImpl` | `flcr.storage.type=cos` | 腾讯云 COS |
| `OssFileStorageServiceImpl` | `flcr.storage.type=oss` | 阿里云 OSS（桩实现） |

### 7.2 上传流程

```
ImageUploadService.upload(file, scene)
  → ImageModerationService.validate(file, scene)  # 格式+大小校验
  → FileStorageService.store(file, sceneDir)      # 上传到存储
  → ImageModerationService.moderate(url, scene)   # 内容审核
  → 返回 URL
```

失败时自动清理已存储文件。

### 7.3 审核策略

| 环境 | 实现 |
|------|------|
| dev | `NoOpModerationServiceImpl` — 仅校验格式和大小 |
| cloud / prod | `CosModerationServiceImpl` — 腾讯云 COS CI 内容审核 |

### 7.4 图片场景

| 场景 | 枚举 | 大小限制 |
|------|------|---------|
| 用户头像 | `AVATAR` | 2MB |
| 用户背景 | `BACKGROUND` | 5MB |
| 菜谱封面 | `RECIPE_COVER` | 5MB |
| 菜谱图片 | `RECIPE_IMAGE` | 10MB |

## 11. 已知限制

| 限制 | 影响 | 缓解 |
|------|------|------|
| 卡路里估算不准确 | LLM 估算，非真实营养数据 | 仅参考展示 |
| 菜谱发布封面与图片非原子性 | 封面成功 + 图片失败 → 封面成为孤儿文件 | 可接受（文件可后续清理） |
| `buildSingleCommentDTO` N+1 查询 | 回复评论的每条 user 都单独查 DB | 仅影响评论区，数据量小 |
| OSS 文件存储为桩实现 | 选择 OSS 时返回占位 URL | 需实现 `OssFileStorageServiceImpl` |
| Mapper 集成测试需 MySQL | CI 环境中 Mapper 测试全部跳过 | 本地方可完整运行 |
| LLM 输出不稳定 | 偶有格式偏差 | `FlexibleIntegerDeserializer` + 正则兜底 + 空值校验 |
